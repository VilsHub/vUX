02Your own handle

        

            Set config.myResizeHandler to a class name and the module stops building
            handles: it listens for a mousedown on your element instead. The grip below is a
            sibling of the panel it resizes, not a child of it, and it holds an icon — a mousedown
            landing on that icon still counts, because the module walks up from the event target.
        


        

            

                config.myResizeHandler = "grip"

Content

                    
Nothing here is managed by vUX. The sidebar has a width, this column is flex:1, and the browser does the rest.

                    
The grip carries no x or y class. It does not need one: direction is "x", which leaves the module only one axis to pick.

                

            

        

    






    

        
03All four edges

        

            A handle grows the element in the direction it faces. Drag the left handle left, or the
            top handle up, and the box gets bigger — the travelled distance is inverted for those two
            edges.

            The module writes a size, never a position. Growing leftward or upward is
            this page anchoring each box to the far side of its cell with flexbox; without that the box
            would still change size, but it would visibly grow the other way.
        

    






    

        
04Teardown

        

            destroy() unregisters the module's listeners and removes the handles it
            injected. Anything hosting a Resizer inside a view that comes and goes — an SPA route, a
            modal — needs it.
