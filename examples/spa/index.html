This example needs its own dev server.

It is a real single-page app: it uses root-absolute paths and needs a history fallback, so that a deep link like /user/7 serves index.html instead of 404ing. A plain static server at the repository root cannot do either — which is why this page is currently showing no routed content. Run: 

cd examples/spa
python3 server.py

then open http://localhost:8931/. This notice disappears once the engine boots.

Routing without the reload.

Click a link: the URL changes, the page title changes, history and the back button work — and the document is never re-fetched. Only #contentBoundary is swapped.

01What to watch

Client-side routing with no rebuild of the shell: only #contentBoundary changes. The diagnostics panel below prints every argument each callback receives.

/;id

Named route params

/user/;id:[0-9]+ validates the segment by regex and delivers it as params.id to the boot, click and history callbacks.

User 7 renders its id from params, not from the URL.

▁▁

Progress on fetch only

preClickCallback shows the bar, the load callbacks complete it. A cached route never fetches, so it never shows one.

Click User 7 twice — the bar appears only the first time.

⤫

Route teardown

Leaving /table fires that route's exitCallback, which stops the ticker and destroys the DataView. Other routes fall back to the global one.

Watch for [exit] in the log.

02Shipping a new release

Everything the engine fetches stays in sessionStorage — and that survives a reload, even a hard one. config.cacheVersion ties the cache to a release: when the value changes, the engine empties its cache and the next navigation fetches fresh. This page reads it from /version.json before initialize().

try it
  1. Click User 7 — fetched, so the progress bar shows.
  2. Click it again from another route — served from cache, no bar.
  3. Ship a release: type a new version below and set it, or edit examples/spa/version.json on disk and press Check.
  4. Click User 7 — the bar is back: the cache was emptied.
