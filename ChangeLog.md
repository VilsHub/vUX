# Changelog
## v4.0.0
## Added
- domDrawer module
- $$.styleElement() feature
- slideSwitch sub module to custom form module
- blur overlayType to modalDisplayer module
- optionStateStyle to selectCustom input
- wrapAttribute property to both custom select and datepicker
- utility namespace ($$), with some modules moved to it
- return datatype option to Ajax.Create() static method
- Resizer module
- Slide utility
- SPAEngine module for redering SPA (Single Page Application) with CSR (Client server rendering)
- $$.getURLParams()
- DataView module (vUX-dataView.js) — keyed data-to-DOM binding for hot-update views (targeted cell updates, node-moving sort/filter)
- Modal stacking in ModalDisplayer — a trigger inside a displayed modal opens a new layer on top; one stack shared across instances; closeAll() to unwind it
- SPAEngine named route params (;name and ;name:regex pattern segments), with route params/data passed to boot, click, history and fallback callbacks
- SPAEngine route exit hook (routes.<name>.exitCallback, falling back to config.exitCallback) fired before a route's content is replaced
- Documentation set under doc/ — index plus SPA engine, progress indicator, data view, modal displayer and form components guides
- Runnable examples: SPA app with bundled dev server (examples/spa/), modal demo exercising all four effects, stacking and both overlay modes (examples/modal/), form components demo exercising all six builders (examples/form/)
- Live table page in the SPA example demonstrating DataView and the route exit hook
- CLAUDE.md project instructions and the per-change logging convention under changelog/<feature>/
- AutoWriter.stop() — cancels a run in progress and clears its timers
- Auto writer guide (doc/auto-writer.md) and runnable example (examples/autowriter/) with a live playground over every config property
- Example page design standard in CLAUDE.md — module examples are designed pages, not bare demos — and the requirement to record every change in ChangeLog.md
- Shared example design system (examples/shared/example.css) — one palette and one set of primitives across every example page
- Live config controls, a hero that leads with the working component, and a validation section printing real thrown errors, on the modal, form and SPA example pages
- Resizer.destroy() — removes the module's listeners and any resize handlers it injected, and releases a drag in progress
- Runnable Resizer example (examples/resizer/) — both axes at once, a playground over every config property, a consumer-supplied drag handle, all four edges, teardown, and the validation errors
- Resizer guide (doc/resizer.md) — the handle contract, edge growth, bounds, styling and specificity, teardown, and the module's mouse-only and keyboard limits
- destroy() on every component — AutoWriter, Carousel, DOMDrawer, FormValidator, ListScroller, ModalDisplayer, ProgressIndicator, SPAEngine, TimeLineList, ToolTip and TouchHandler, plus each of the six FormComponents widgets — detaching the listeners, timers and animations the component started and removing the DOM it injected, so a component can be torn down without leaving anything bound to the page
- $$.attachEventHandler() now returns a handle whose detach() removes the delegated listener again; calls that ignore the return value are unaffected
- destroy() on the object returned by CShapes().animatedRectangle() — stops the animation and clears the canvas, where stop() leaves the last frame painted
- ToolTip.destroy() restores the original title attribute on every element it took one from
- Component module (vUX-component.js) — build your own reusable component from your own markup: a `<template>` marked with `data-v-*` bindings, cloned and managed by vUX, with `mount()`, `update()`, `destroy()` and keyed `sync()`
- Component bindings: `data-v-field` (text), `data-v-bind` (attributes), `data-v-on` (events), `data-v-ref` (named nodes), `data-v-show` and `data-v-class` (truthiness toggles) — every value a plain field name, never an expression
- Component nesting: a child mounted with `instance.mount()` is owned by its parent and destroyed with it, and `config.onMount`/`onUpdate`/`onDestroy` are where nested vUX components are attached and released
- DataView rows now accept the full binding set — `data-v-bind`, `data-v-on`, `data-v-ref`, `data-v-show` and `data-v-class` work alongside `data-v-field` — with `config.handlers` and `config.formatters` to drive them
- Component guide (doc/component.md) — the binding contract, both template forms, keyed lists, nesting, the custom-element recipe, and the full error list
- Runnable Component example (examples/component/) — every binding under live control, keyed lists keeping their nodes through a sort, nesting with a ToolTip attached and released, and every validation error raised on demand
- Carousel config changes on a live carousel — delay, speed, slideEffect, buttonStyle and touchResponse now take effect after initialize() and start() instead of only before them
- Carousel guide (doc/carousel.md) — the required consumer CSS, every config property, the generated markup, and the error list
- Runnable Carousel example (examples/carousel/) — a live playground over every config property, two carousels with independent dot styles, swipe and hover pause, and the validation errors
- TimeLineList guide (doc/timeline-list.md) — the attribute contract, the three specificity tiers, centring custom markers, the generated markup, limits, and the error list
- Runnable TimeLineList example (examples/timelinelist/) — a live playground over every data attribute, three differently-styled lists on one instance, refresh() for lists that arrive later, and the validation errors
- ListScroller config.scrollSpeed and config.paddingRight now work: scrollSpeed is the duration of one button scroll in milliseconds (0 jumps), and paddingRight leaves room after the last item inside the scroll range
- ListScroller buttons, inactiveButtonClassName, wrapperStyle, hasButtons and the paddings can be changed on a running scroller
- ListScroller buttons get aria-disabled matching their inactive state
- ListScroller guide (doc/list-scroller.md) — the container, list and button contract, every config property, the markup it produces, limits and the error list
- Runnable ListScroller example (examples/listscroller/) — a live playground over every config property, button state following swipes, resizes and new items, a buttonless row, and the validation errors
- Skeleton module (vUX-skeleton.js) — placeholder screens derived from the template you already wrote for the real content: fields become text bars, images media blocks, controls filled blocks, and your card, padding and grid are kept, so the skeleton has the layout of what replaces it
- Skeleton `data-skeleton` attribute — `text:N`, `circle`, `circle:<size>`, `rect`, `rect:<w>/<h>`, `media`, `keep` and `skip` override what an element is inferred to be
- Skeleton timing — `config.delay` keeps a fast load from flashing a skeleton at all, `config.minDuration` keeps a slow one from flickering off, and `hide()` returns a promise so you render once it is down; `during(promise)` wraps the whole flow
- Skeleton mask mode — with no template, masks the container's existing content in place for a refresh, and puts the same nodes back afterwards
- Skeleton guide (doc/skeleton.md) — the two modes, what becomes what, `data-skeleton`, timing, styling through custom properties, accessibility, limits and the error list
- Runnable Skeleton example (examples/skeleton/) — a feed reloading at three speeds, a template beside its rendered card and derived skeleton, a playground over every config property, a with/without timing comparison, mask mode with a byte-for-byte check, and the validation errors
- SketchPad module (vUX-sketchPad.js) — a canvas drawing surface, extracted from the Sketchpad whiteboard app: rectangles, ellipses, diamonds, triangles, pentagons, hexagons, stars, lines, arrows, freehand pen, text, font icons and images, with selection, marquee, move, resize, duplicate, delete, undo/redo, wheel zoom and pan
- SketchPad connectors — drag from a shape's border to another shape's to draw an arrow bound at both ends that re-routes when either shape moves or resizes; pressing Ctrl while drawing pins a joint, which curves the connector at that point
- SketchPad scene as data — `elements` returns the scene as plain JSON and `load()` restores it (optionally as an undoable step); `exportCanvas()` renders it cropped to its content at any scale and background for PNG export or thumbnails
- SketchPad constrained mode — `config.tools` limits the tools offered, `config.panZoom = false` fixes the view, `config.bounded` keeps every shape inside the surface and `config.maxElements` caps the scene, for a pad that marks out one region over an image
- SketchPad stamps and icons — `createStamp()` turns SVG source into a stamp the stamp tool places, with black-only SVGs retinted by the fill colour; `icon` arms the icon tool with a glyph from any loaded font
- SketchPad works with touch and pen as well as the mouse, and several pads can share a page: pointer events are the canvas's own and keyboard shortcuts go to the focused pad (or the whole document, with `config.keyboardScope`)
- SketchPad guide (doc/sketch-pad.md) and runnable example (examples/sketchpad/)
- FontSplash module (vUX-fontSplash.js) — a splash screen whose loader is a word set in your own font, filled with a gradient that flows through the letters while they fade in a wave; `animation` also offers `flow`, `breathe` and `none`
- FontSplash waits for its font — `config.font` takes a family the page declares, or a face of its own from a URL, a CSS src list or an ArrayBuffer; the backdrop goes up at once and the word appears when the font is ready or `config.fontTimeout` runs out, with `fontStatus` reporting which
- FontSplash covers the whole viewport with `new FontSplash()`, or a single element with `new FontSplash(el)`; the `vux-fs-cloak` class on `<html>` hides the page from its first paint until a full-screen splash is up
- FontSplash progress mode — `setProgress(0…1)` fills the word with the gradient from the left over a flat track, and `setProgress(null)` returns to indeterminate
- FontSplash timing — `config.delay` keeps a fast load from showing a splash at all, `config.minDuration` holds the word once it has appeared, `hide()` returns a promise that resolves after the `fade`, `lift` or `zoom` exit, and `during(promise)` wraps the whole flow
- FontSplash guide (doc/font-splash.md) and runnable example (examples/fontsplash/)
- SPAEngine `config.cacheVersion` — ties the engine's sessionStorage cache to a release: when the value changes (e.g. a build id read from a version.json), cached route content is emptied, at `initialize()` or at once on a running engine, so users stop seeing fragments from before a deploy
- SPAEngine `clearCache()` — empties every route, page and section the engine has cached, leaving the rest of sessionStorage (such as auth state) alone
- Release section in the SPA example (examples/spa/) — boots from a version.json, sets a new cacheVersion or calls clearCache() on the live engine, and shows the engine's storage keys emptying
- SPAEngine `loggedIn` property — the app tells the engine whether a user is signed in (set it before `initialize()` on every page load, `true` after sign-in, `false` on sign-out), and protected routes read it
- Minified build: ./minify.sh writes a minified copy of the library (about 60% smaller JS) to dist/<version>/ with the same file layout, so a page switches to it by pointing data-library-root and its imports at that folder
- Core utilities guide (doc/core.md) — `$$`, every `$$.sm()` manipulator, slide/flip/animate/filter in detail, delegated events, data, time and environment utilities, the global helpers and built-in extensions, the error list, and a table of the calls known to be broken in this release
- Runnable core utilities example (examples/core/) — a gradient headline turned by `animate()`, a flip card, a selection board with every class and visibility method, slides, an easing lab, filters, overlays, delegated events, a live countdown, the built-in extensions evaluated on the page, and the validation errors and known defects triggered on demand
- ModalDisplayer "drop" effect — the modal drops from above the viewport into place and rises back up on close; set `config.effect = "drop"`
- ModalDisplayer "slideLeft" and "slideRight" effects — the modal slides in sideways and stays docked to an edge as a full height panel instead of centring: slideLeft enters from the right, docks right and leaves back out to the right; slideRight mirrors it on the left
- MessageBox module (vUX-messageBox.js) — notification messages posted with `show()` or the typed shorthands `info()`, `success()`, `warning()` and `error()`; each stays for `config.duration` (0 keeps it until closed) and leaves on its own
- MessageBox effects — `drop` (the default) falls from the top of the window and rises back out, `slideLeft`/`slideRight` slide in from an edge and leave through it, plus `fade` and `none`; the movement is the core slide utility's, and under reduced motion every effect becomes a fade
- MessageBox alignment — `config.alignment` lands messages on the left, centre or right; messages stack without jumping, every instance on a page shares the same lanes, and on a narrow window all of them share the centre lane
- MessageBox timer pauses while the pointer is over a message or focus is inside it, with a countdown bar that holds with it; plus a close button, close-on-click, `maxVisible`, light and dark themes, and `onShow`/`onClose` callbacks that report why a message closed
- MessageBox handles — `show()` returns a handle whose `close()` removes the message when your code decides, and content may be an element carrying your own controls
- MessageBox guide (doc/message-box.md) and runnable example (examples/messagebox/)
- Marquee module (vUX-marquee.js): an endless scrolling strip from a container whose items are written once; it clones them until any width is covered, measures one loop to the pixel so the seam never shows, and rebuilds on resize or when `refresh()` adopts new items
- Marquee config: `speed` in pixels per second, `direction` (`left` or `right`, reversing in place), `gap`, `fade` for a masked edge fade, `pauseOnHover` (keyboard focus counts too) and `respectReducedMotion`; every setting applies to a running strip without restarting its loop
- Marquee `pause()`, `play()`, `refresh()` and `destroy()`, plus `paused` and `moving` getters; clones are hidden from screen readers and the tab order and carry no ids, but stay clickable
- Marquee guide (doc/marquee.md) and runnable example (examples/marquee/)
- CShapes rectangles take `config.radius` for rounded corners, on both `fixedRectangle()` and `animatedRectangle()`; the line keeps one even thickness all the way round
- SPAEngine mounts a route only once the stylesheets its fragments carry have loaded: the content and every section appear together, already styled, while the previous route stays on screen untouched until then; at boot the page stays hidden until the first route is mounted
- SPAEngine `config.styleTimeout`: the longest, in milliseconds, a fragment waits for its stylesheets before it is mounted anyway (default 3000, 0 to not wait)
- SPAEngine scroll restoration (`config.restoreScroll`, on by default): back/forward and a reload return to the scroll position each history entry had, instead of keeping whatever position the previous route left
- SPA example section "Back to where you were": a live view of the engine's scroll state (current position, the position saved in the history entry, history length, the last restore) and a button to leave from the current spot and come back with Back
- Prompt module (vUX-prompt.js): `alert()`, `confirm()` and `input()` dialogs that resolve a Promise with the answer, replacing the blocking native calls with a styled, themable dialog that sits above every modal on the page and keeps Escape from reaching the page underneath
- Prompt `danger` option: a red OK button and focus starting on Cancel, so a stray Enter cannot confirm a destructive action
- Prompt input validation: `required`, `maxLength`, `inputType` and a `validate()` function that may be async, with OK held off while it runs and the refusal shown under the field
- Prompt queue: dialogs asked for while another is up, from any instance, open in turn instead of on top of each other
- Prompt guide (doc/prompt.md) and runnable example (examples/prompt/): each dialog one click away, a playground over every config property with a log of each answer, a guarded delete, an async-validated rename, two instances sharing the queue, and the validation errors
- FormValidator `validate()` returns true when the field passes and false when it fails
- FormValidator `minSize` and `maxSize` rules (`"maxSize:2MB"`; B, KB, MB or GB) checked against every selected file; they were listed as supported but did nothing
- FormValidator `callBack` functions receive the field as a second argument
- FormValidator default loader: a ring spinner when `config.progressIndicatorStyle` is not set (the loader used to be invisible without it)
- FormValidator guide (doc/form-validator.md) and runnable example (examples/formvalidator/)
- ToolTip `config.html`: tips are plain text by default; `true` sets them as HTML
- ToolTip `tipBoxStyles.backgroundColor`, alongside `arrowColor` and `fontColor`; the arrow follows the background unless `arrowColor` is given
- ToolTip keyboard support: focusing a member shows its tip and blur hides it; the tip has role="tooltip" and the shown member points at it with aria-describedby
- ToolTip guide (doc/tool-tip.md) and runnable example (examples/tooltip/)
- CShapes `arc()`: a progress ring drawn with `draw(canvas, progress, label)`, starting at 12, 3, 6 or 9 o'clock in either direction, with the percentage and a label in the middle, round or butt line caps, a radius that fits the canvas, and an optional animation from the last value shown (`duration`, `easing`, `callback`, `stop()`, `destroy()`)
- CShapes guide (doc/c-shapes.md) and runnable example (examples/cshapes/)
- CShapes `arc()` fonts reset to the radius-scaled default when set to `null` or `""`

- `camelToCSSstandard("fontSize")` now returns `"font-size"` instead of `"fontundefinedize"`
- `validatePhoneNumber(value)` now checks the value it is given; it used to throw a ReferenceError
- `$$.randomString(n)` now always returns `n` characters drawn from all 62 letters and digits; it sometimes returned fewer, repeated `T` and never produced `j` or `Y`. It and `$$.randomInteger()` now throw for non-integer arguments, as their messages always said
- `ScreenBreakPoint` now accepts either breakpoint on its own, or no argument, using the defaults for what is left out; leaving one out used to throw
- `$$.browserType()` now recognises desktop and iOS Safari, Opera's `OPR` agent and headless Chrome, and reports `name: "unknown"` for an agent it doesn't know instead of throwing
- `flip.card()` with `axis: "z"` now turns the card; it wrote an invalid transform. `frontClass`, `backClass` and `axis` are now each checked as strings
- `filter()` with options now cleans up after its pulse: the transition and listener it added are removed, so later `filter()` calls on the element are no longer transitioned and reset to `none`. `callBack` runs on a timer instead of freezing the page, `duration` defaults to 200ms when left out, `init` works with a single filter name, and an unsupported single name now throws instead of being ignored
- `slide.toRight()`, `toTop()` and `toBottom()` now throw on invalid options, as `toLeft()` does, instead of logging the error and running anyway. `toLeft()` errors no longer carry a doubled `Error: Error:` prefix, an invalid `positionProperty` is named in a full message, and `positions` without the axis a direction needs is now rejected
- `slide.toTop()` and `slide.toBottom()` now default `use` and `positions` as the other directions do; leaving `use` out used to throw
- `slide.toBottom()` with `dimensions` but no end height now opens to the content's height; the unitless height it wrote was ignored
- `$$.ajax(options)` no longer requires a return type; left out, it sends `Accept: */*`
- `$$.sav(selector)` without `"visible"` or `"hidden"` now throws a descriptive error instead of a bare TypeError
- The overlay from `addOverlay()` now covers a padded host from its edge and follows its `border-radius`, and `core.css` no longer turns every `<div>` child of the host into a full-size absolute layer
- ModalDisplayer content no longer blinks as the flip, box, drop, slideLeft and slideRight effects finish: the modal that animated in is the one left on screen, so typed and autofilled form values and id-based styles stay put instead of dropping out for a few frames, and the closing effect plays with those values too
- ModalDisplayer no longer snaps wider or narrower as the flip, box, drop and split effects finish: the effect is now sized to the width the modal is shown at (its configured width) rather than the hidden modal's natural content width, so its height matches too
- ModalDisplayer's split effect now shows the modal's right side in its right half; both halves used to show the left side, so the two halves never formed the modal until the effect ended
- ModalDisplayer's split effect no longer shows browser-autofilled fields in one half and empty fields in the other; the halves' copies of the form are no longer autofilled while they move
- CShapes `animatedRectangle()` accepts a numeric `iterationCount`; any number used to throw a ReferenceError, so only `"infinite"` worked
- CShapes rectangles are sharp on high-density screens; the canvas is now sized by the device pixel ratio instead of drawn at CSS-pixel resolution and stretched
- CShapes `animatedRectangle()` no longer re-strokes every earlier frame's rectangle on each frame, so a cycle no longer gets slower the longer it runs
- Calling `draw()` again on a running `animatedRectangle()` restarts it; it used to start a second loop alongside the first, doubling the speed, and a `stop()` that landed on a cycle's last frame was ignored
- A repeating `animatedRectangle()` no longer jumps at the start of each cycle when its dash pattern does not divide 100px (the default `[10, 2]` did); each cycle now moves a whole number of dash periods
- `animatedRectangle()` with an easing that does not end on exactly 1 now finishes its cycle and runs its callback, and a `duration` of 0 completes its cycles instead of stopping without the callback
- `animatedRectangle().draw()` no longer requires the canvas to have an id
- `$$.sm(el).animate()` no longer starts below its start value: the first frame's time fraction could be negative, so the first value drawn was slightly under `startValue` (or under the remembered end of the previous run)
- SPAEngine no longer paints a fragment before its stylesheets arrive: a section or content mounted on boot, click or back/forward used to show unstyled for as long as its CSS took to load, so an image with no size of its own (such as a header logo) could fill the screen
- SPAEngine flush selectors are emptied when the new route is mounted, not as soon as the link is clicked, so a header no longer goes blank while the next route loads
- SPAEngine: after back/forward, clicking the link that last loaded the content node loads its route again; it used to be ignored, leaving the history entry's content under the clicked route's sections
- SPAEngine: when two clicks race, only the last one is mounted; a slower earlier one used to mount its sections over the later route's
- SPAEngine: a section that fails to fetch is logged and skipped, and the rest of the route still mounts; a failed or fallback response is no longer cached as the section
- AutoWriter `stop()` and `destroy()` now cancel a callback that is waiting out `callBackDelay`; it used to run anyway, so a callback that called the writer again threw "called on a destroyed AutoWriter"
- SPAEngine no longer adds a second history entry for the entry page at boot, so the first Back press leaves the page instead of appearing to do nothing; the boot entry also keeps the URL's query and `#hash`, which used to be dropped
- SPAEngine: a route fragment that fails to load is reported in the console (as a failed page or section already was) and its link can be clicked again; it used to throw a ReferenceError while building a blocking alert, and leave the link stuck
- ProgressIndicator: the first linear bar shown in a page now animates; it used to jump straight to its first stop, and a style 3 bar then never moved on to its slow and crawl phases (later bars were fine)
- FormValidator `required`, `minLength`, `maxLength` and `email` reported an error on every valid value in email, password, number, tel, url and other non-"text" inputs, and in inputs with no type attribute
- FormValidator no longer leaves an old error showing after the field is corrected and validated again
- FormValidator writing a message straight after a clear (a click into the field, then a failed check) no longer loses the new message when the old one finishes fading
- FormValidator message text gets its colour even when no transition runs (reduced motion, a hidden form); it used to stay transparent
- FormValidator changing a field's message type or side (error to warning, bottom to right) restyles or moves the box instead of keeping the old one
- FormValidator only error messages make `formOk()` false; a warning or success message (for example "Username available") used to block submission
- FormValidator forms on the same page no longer affect each other: a click in one form no longer clears another form's messages, each form's messages take that form's own colour variables, and a feedback box or loader in one form is no longer emptied or removed by another
- FormValidator `submit()` no longer leaves the form locked behind its overlay when the server answers anything other than 200, 404, 405, 419 or 500, or cannot be reached: any 2xx counts as success and every other answer shows an error feedback box
- FormValidator `submit()` sends its `headers` argument (it was ignored), sends the fields in the query string for GET (they were dropped), ignores a second call while a request is pending, and checks its arguments before locking the form
- FormValidator feedback button: no longer submits the form it sits in, acts on click instead of on focus (tabbing onto it used to dismiss the box, and in Safari clicking it did nothing), and `showFeedback()` called on its own now shows the overlay it lives in
- FormValidator feedback box: a warning is centred when `feedbackModalStyles` has no warning entry, and `labels` with only a title (or only a button label) keep the other default instead of leaving it empty
- FormValidator loader: hidden while the feedback box shows, and no longer duplicated on every submission
- FormValidator custom progress animation: `onReceive` runs once per request; it used to run on every message written, including every failed `validate()`
- FormValidator rule keys may contain colons (`"match:/^a:b$/"`), `match` keeps its regex flags and escaped slashes, `ext` is case-insensitive, `fullName` copes with double spaces, `trim` runs before `required`, and a `callBack` returning false writes its first message
- FormValidator rule messages containing ":-" are kept whole; only a leading `e:-`, `w:-` or `s:-` sets the type
- FormValidator `ext` with no file chosen, `required` on a select with no options, and `message.write()` with a NodeList no longer throw; radio groups from `form.elements` are accepted
- FormValidator `logServerError()` defaults each entry's location to bottom and writes server messages as text
- FormValidator `destroy()` also removes the message boxes and the classes and attributes it put on fields
- FormValidator config: `progressAnimationCallbacks` needs both `onSend` and `onReceive` (a missing one crashed later), `loaderLocation` can be set before `submitButtonClass` and "form" no longer needs it, and an unsupported `submissionMethod` throws instead of being ignored
- FormValidator default warning and success colours are readable (dark text on a light fill); the warning used orange text on dark brown
- `FormValidator.format.currencyField()` keeps decimals (1234.56 became "1,234,.56") and always returns a string; `wordSeperator()` validates its repeat count and no longer adds a document listener per call; `integerField()` rejects non-text inputs as documented
- `validateEmailAddress()` (used by the FormValidator `email` rule) accepts sub-domains, hyphenated domains and "+" in the local part
- ToolTip `on()` works (it threw a ReferenceError), `off()` works on members set up by `initialize()` (it threw "No tool tip applied") and hides a tip that is showing
- ToolTip shows when the pointer is over a child of a member (an icon in a button) and stays up when moving onto one
- ToolTip `tipBoxStyles` validates its keys and values (the checks never ran, and more than two keys threw a ReferenceError), no longer writes "undefined" colours, and applies when set after `initialize()`
- ToolTip stays inside the window: fixed to the viewport, flipped below the pointer near the top edge and pushed in from the side edges, with the arrow kept on the pointer
- ToolTip text is set as text, so a title containing markup can no longer inject HTML
- ToolTip hides on scroll, Escape or a touch elsewhere, so a tip opened by a tap no longer stays up
- ToolTip error for a bad `className` names ToolTip instead of datePicker
- ToolTip `refresh()` no longer turns back on a member switched off with `off()`
- ToolTip keeps a member's own `aria-describedby`, adding the tip's id while it shows; it used to overwrite and then remove it
- ToolTip instances on the same class: destroying one no longer removes the tip box and the titles from under the other, and `config.html` set on either applies
- CShapes `draw()` on anything but a canvas throws a clear error instead of "getContext is not a function"
- FormValidator `minLength` / `maxLength` without a whole number (`"maxLength:abc"`) throw instead of passing every value, and a click on markup inside the feedback button's label works
- FormValidator `destroy()` during a pending `submit()` aborts the request; the answer used to arrive at the torn-down form and throw
- FormValidator `showFeedback()` ends the loading state (button loader, custom `onReceive`), so a custom animation no longer keeps running behind the feedback box
- FormValidator `customStyles` passed with a message update apply to the box already showing, and long messages under a field wrap instead of running off a narrow screen
- ToolTip keeps its 320px maximum width (or your own `max-width`) on wide windows; an inline width set from the window size used to override it
